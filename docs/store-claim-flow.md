# 店舗ページ量産フロー マニュアル（クレーム招待）

管理者が店舗ページを先に作成し、招待リンクを店舗営業者に渡して「承認」してもらうことで、
営業者のアカウントを自動発行しつつ店舗を量産するための運用手順です。

---

## 全体の流れ

```
① 管理者が店舗ページを作成（非公開状態で作られる）
        ↓
② 管理者が「招待リンク / QRコード」を発行し、営業者に手渡し
   （LINE・メール・口頭・チラシなど、渡し方は自由）
        ↓
③ 営業者がリンクを開く
   → 自分のお店のページをプレビュー確認
   → 名前・メール・パスワードを入力して「承認」
        ↓
④ 営業者のアカウントが自動作成 ＋ 店舗が本人に紐付き ＋ 一般公開
   そのままログイン状態で店舗編集画面へ
```

> **公開タイミング**: ②③の段階では店舗は **非公開（isActive=false）**。
> 営業者が「承認」して初めて一般公開されます。営業者の同意を得てから集客に使える安全な設計です。

---

## ① 店舗ページを作成する（管理者）

1. 管理画面 `/admin/stores`（店舗管理）を開く
2. 右上の **「新規店舗作成」** をクリック
3. 店舗名（必須）・説明・カテゴリ・エリア・Web/SNS を入力して **「作成」**
4. 一覧に「**非公開 / 未割当**」の状態で店舗が追加される

> 画像や詳細項目（おすすめ商品・こだわり等）は現状この作成フォームにはありません。
> 必要であれば作成後にフェーズ2の編集機能で追加します（今後の拡張予定）。

---

## ② 招待リンク / QRコードを発行して渡す（管理者）

1. `/admin/stores` の一覧で、対象店舗の行にある **🔗（リンク）アイコン** をクリック
2. ダイアログに **招待URL** と **QRコード** が表示される
3. URL右の **コピーボタン** でURLをコピー、またはQRコードを保存
4. LINE・メール・口頭・印刷チラシなど、好きな方法で営業者に渡す
5. 渡したあと、一覧のオーナー欄が **「招待中」** バッジに変わる

| 操作 | アイコン | 説明 |
|---|---|---|
| 招待リンク発行 / 再表示 | 🔗 Link2（緑） | リンクとQRを発行・表示。再発行すると前のリンクは無効化 |
| 招待を取り消し | ⊗ XCircle（オレンジ）※招待中のみ表示 | 発行済みリンクを無効化し「未割当」に戻す |
| 既存ユーザーを割当 | 👤+ UserPlus（青） | 既にアカウントを持つ人を手動で紐付ける（招待を使わない場合） |

> **リンクの有効期限は60日**です。期限切れ・紛失時は 🔗 から再発行してください（旧リンクは自動で無効になります）。

---

## ③ 営業者がページを承認する（店舗営業者の操作）

営業者がリンク（例: `https://tenmusubi.net/stores/claim/xxxxx`）を開くと：

1. 「**あなたのお店のページを作成しました🎉**」というプレビュー画面が表示される
2. 店舗名・カテゴリ・エリア・説明・画像を確認できる
3. 下部のフォームに **お名前 / メールアドレス / パスワード（8文字以上）** を入力
4. 利用規約に同意して **「承認してページを公開する」** をクリック

これだけで完了です。営業者は新規登録ページに行く必要はありません。

---

## ④ 承認後に起きること（自動）

- 営業者の **vendor（出店者）アカウントが自動作成**される
  - 招待リンク経由のため、メール認証は済んだ状態で発行されます
- 店舗が **その営業者に紐付く**（オーナー設定）
- 店舗が **一般公開**される（isActive=true）
- 営業者はそのまま **ログイン状態** になり、自分の店舗一覧 `/stores/my` へ移動
- 管理画面の一覧では、オーナー欄に営業者名が表示され、状態が「**公開中**」に変わる

---

## 状態（ステータス）の見方

`/admin/stores` 一覧のオーナー欄・状態欄での見え方：

| 表示 | 意味 |
|---|---|
| オーナー欄「未割当」 | 作成済みだが、まだ招待していない |
| オーナー欄「招待中」 | 招待リンクを発行済み。営業者の承認待ち |
| オーナー欄に氏名表示 | 承認済み or 手動割当済み（紐付け完了） |
| 状態欄「非公開」 | 一般公開されていない（承認前） |
| 状態欄「公開中」 | 一般公開中（承認後 or 手動公開後） |

## よくあるケース・トラブル対応

**Q. 営業者が入力したメールが既に登録済みだった**
→ 「ログインしてから承認してください」と表示されます。営業者がログインした状態で
もう一度リンクを開いて承認すると、**そのアカウント**に店舗が紐付きます。

**Q. リンクの有効期限が切れた / 紛失した**
→ 管理画面の 🔗 から再発行してください。古いリンクは自動的に無効になります。

**Q. 間違えて招待した店舗を取り消したい**
→ 「招待中」の店舗にある ⊗ で取り消せます（承認後は取り消せません）。

**Q. 承認前のページは検索などに出てしまう？**
→ 出ません。承認まで非公開のため、招待リンクを知っている人だけがプレビューできます。

**Q. アカウントを使わず、ただページを公開だけしたい**
→ 「既存ユーザーを割当（👤+）」で運営側ユーザー等に紐付けるか、別途編集画面で公開します。
（※今回のフローは「承認＝公開」のため、営業者承認を前提とした運用が基本です）

## 技術メモ（開発者向け）

- **スキーマ**: `Store` に `claimEmail` / `claimStatus`(`none`|`invited`|`claimed`) / `invitedAt` / `claimedAt`
- **トークン**: 既存 `VerificationToken` を `store-claim:{storeId}` プレフィックスで流用（有効60日）
  - `src/lib/tokens.ts`: `createStoreClaimToken` / `verifyStoreClaimToken` / `deleteStoreClaimToken`
- **API**
  - `POST /api/admin/stores/[id]/invite` … リンク+QR発行（要admin）
  - `DELETE /api/admin/stores/[id]/invite` … 招待取り消し（要admin、承認後は不可）
  - `GET /api/stores/claim/[token]` … プレビュー（トークン非消費・公開）
  - `POST /api/stores/claim/[token]` … 承認・アカウント作成・公開（公開）
- **画面**
  - 管理: `src/app/admin/stores/page.tsx`
  - 営業者: `src/app/stores/claim/[token]/page.tsx`
- **本番DB（Turso）**: スキーマ変更は `prisma/migrate-prod.ts` に ALTER 文を追加済み。
  `npm run build:prod` 時に自動適用される（詳細は `CLAUDE.md`）。
